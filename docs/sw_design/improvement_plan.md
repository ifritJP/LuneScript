# LuneScript の改善項目

`impression.md` (LuneScript を使ってみた感想) をふまえて、修正した方が良い項目と修正方法を、優先順位を付けてまとめる。

- 書いた時点: 2026-10-17 (`support_direct_wasm` の `6656e8f3` の時点)
- 優先順位の考え方: 正しさに関わるもの → 不具合を見つける仕組み → 書く人の負担を減らすもの → 資料・性能の順

## 優先度: 高 (正しさ・不具合を見つける仕組み)

### 1. go 版 lnsc で、実行中の Lua のエラーが異常終了になる

- 問題: `lnsc ... exe` で Lua のエラーが起きると、`PANIC: unprotected error` と全 goroutine のダンプを出して終了する。
- 修正:
  - `runtime_go/luaMisc.go` の `RunLoadedfunc()` で、`lua_call` の代わりに `lua_pcall` を使う。
  - エラーのメッセージを取り出して、Lua 版と同じく `lua: <メッセージ>` を表示し、終了コード 1 で終える。
  - `test-go` に、実行時エラーで終わるテスト (終了コードと stderr を確認する) を足す。

### 2. 出力先をまたいだ共通の比較テスト

- 問題: Lua 版と go 版の比較 (`test-go`) と、Lua 版と wasm 版の比較 (`test-wasm`) が別々の仕組みになっている。
  go 版だけの不具合が残っていた。
- 修正:
  - テストのソースを 1 か所に集め、同じテストを全ての出力先で実行して、Lua 版の結果と diff する共通の make のターゲットを作る。
  - 出力先ごとに除外する印 (`/*nolua51*/` と同じ形で `/*nogo*/`・`/*nowasm*/`) を使えるようにする。
  - 今の `test/testGo.lns` と `test/wasm/`・`test/tutorial/` をこの仕組みに移す。

### 3. Lua と go の意味の違いの洗い出し

- 問題: wasm の作業中に見つけた go 版の不具合 5 件は、どれも Lua と go の意味の違いから来ていた
  (`%c`、2^53 を超える整数、シフト、ビット演算の優先順位、`form` への変換)。似た不具合が残っている可能性が高い。
- 修正:
  - 演算子・組み込み関数ごとに、境界値を使うテストを 2 の仕組みに足す
    (負の数の `/`・`%`、オーバーフロー、`-0.0`、NaN、2^63 付近、実数の文字列化など)。
  - 違いが見つかったら、`convGo` で括弧・ランタイムの関数を出力して合わせる。
  - 設計上合わせない違いがあれば、一覧にして文書に書く。

## 優先度: 中 (書く人の負担を減らす)

### 4. コンパイルエラーのメッセージの改善

- 問題: 原因がメッセージからわかりにくい例が多い。
- 修正: よくある誤りに、直し方の候補を出す。
  - `if! ... elseif`: `illegal exp` の代わりに「`if!` は `elseif` を持てない。`if!` を入れ子にするか、`let!` を使う」と出す。
  - mutable の不一致 (`@Shape <- &Rect`): 代入元が `let` で宣言した変数なら「`let mut` で宣言する」と出す。
  - Map への `#`: 「Map に `#` は使えない。`foreach` で数える」と出す。
  - `when!` に変数でないものを書いた場合: 「`if! let x = ...` を使う」と出す。

### 5. 構文の不足を補う

- `continue` を追加する。
  Lua 5.2 以降は `goto` で、Lua 5.1 は `repeat ... until true` で包んで `break` する変換で実現する。
  go と wasm では、それぞれの continue と分岐に変換する。
- `if! ... elseif` を使えるようにする。
  `if! let x = a { } elseif cond { }` を、`if! ... else { if ... }` に展開すれば良い。
- Map の要素数を取る方法を用意する (`#` を許すか、`len()` のようなメソッド)。
  Lua 版は `next` で数える処理になり、go と wasm は要素数をそのまま返せる。

### 6. 関数型の書き方の統一

- 問題: 引数や戻り値に `fn( int ) : int` と直接書けず、`form` の宣言が必要。
  引数の無い `form` を `f( ## )` で呼ぶと、宣言した型によってエラーになる。
- 修正:
  - 型を書く位置で `fn( 引数 ) : 戻り値` を使えるようにする (中では無名の `form` 型として扱う)。
  - `##` の扱いを、`form` と宣言した関数型の両方で揃える。

### 7. 生成した go のコードを単体でビルドしやすくする

- 問題: 生成したコードをビルドするには、`src/go.mod` を流用してランタイムのソースをコピーする必要がある。
- 修正:
  - `runtime_go` を独立した go のモジュールにする (`go.mod` を置き、タグを付ける)。そうすれば `go get` で取れる。
  - `lnsc ... mkmain` の際に、`go.mod` の雛形も出力するオプションを足す。
  - Lua を使わないプログラムは cgo 無しでビルドできることを、手順に書く。

### 8. Lua の実行時エラーを LuneScript のソースの位置に対応付ける

- 問題: `string.format` の書式の誤りなどが、出力した Lua の位置で表示される。
- 修正:
  - `convLua` で、出力した Lua の行と `.lns` の行の対応表を作る (既存の `.meta` に入れるか、別ファイルにする)。
  - `lnsc ... exe` のエラー表示で、スタックトレースの位置を `.lns` の位置に書き換える。

## 優先度: 低 (資料・性能・細部)

### 9. 変換器を書く人向けの「AST の読み方」の資料

- 修正: `docs/` に、新しい出力先を作る人向けの注意点をまとめる。
  - 暗黙の cast (`ExpCastNode` の `Implicit`) の `expType` は cast 前の型で、cast 後の型は `castType`。
  - `a, b = f()` では、同じ `ExpMRetNode` を値ごとの `ExpCastNode` で包む。
  - str の型 (`builtinTypeString`) の種類は `TypeInfoKind.Class`。
  - builtin のメソッドの getter の `$rawTxt` は `<head>`。
  - 多値・`...` に関わるノード (`ExpMultiTo1`・`ExpToDDD`・`ExpAccessMRet`) の関係。
- AST そのものを変える (`Implicit` の `expType` を cast 後の型にする、など) と既存の変換器に影響するので、まず資料で対応する。

### 10. wasm の変換の最適化

`wasm_benchmark.md` で確認した要因に対応する。

- itable を anyref の配列ではなく型付きのフィールドにして、cast を無くす。
- メソッドの先頭で `self` を 1 回だけ cast し、以降はその局所変数を使う。
- 定数で割る `%` / `/` と定数のシフトは、補助の関数を呼ばずにその場で計算する。
- `for` の増分が定数なら、符号の判定を省く。
- b_closure が `--no-liftoff` で遅くなった原因を調べる。
- 改善するたびに `make bench-wasm` で測り、`wasm_benchmark.md` に記録する。

### 11. `default_async_all` でのクロージャの制限

- 問題: 非同期で使わないクロージャでも、mutable な局所変数を参照できない。
- 修正: 制限の理由 (非同期での共有) をエラーメッセージで示し、回避策 (`__noasync` を付けるなど) を案内する。
  制限そのものを緩めるかは、非同期の設計と合わせて判断が必要。

### 12. `-Werror` の警告への対応の手間

- 問題: `**`・`##` を付ける警告は意図を明示させる良い仕組みだが、直すのに手間がかかる。
- 修正: 警告の位置に自動で `**`・`##` を補う修正オプション (`lnsc --fix` のようなもの) を用意する。

## 進め方

まず 1〜3 を `dev_with_llm` で順に進める。
1 は小さな修正で、2 の共通の比較テストができれば、3 の洗い出しや以降の修正の確認に使える。
